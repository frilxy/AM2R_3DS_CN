# 与上游 AM2R_3DS 的对比（2026-10-31）

上游：`codeberg.org/NattensMadrigal/AM2R_3DS`，最新提交 `b0c705fa`（2026-10-28）。

## 结论速览

- **闪退修复双方独立做到了同一件事**（关掉 denormal），我们的证据链更完整（崩溃转储）。
- 上游把**暂停页按 320 版式排版**——正是我们在查的那类问题的解法，值得直接借鉴。
- 上游还有若干**我们完全没有**的修复与功能，可直接采用。

## 双方都有

| 项 | 上游 | 我们 | 对比 |
|---|---|---|---|
| flush-to-zero | `14e9f9d7` | V1.8.1 起 | 同一修法。我们有崩溃转储（FPEXC/FPINST/PC）作为根因证据，上游提交说明只写"denormals crashed the Metroid fights" |
| 碰撞派发按对象顺序 | `ca66c214` | ✅ `sortInstancesByObjectIndexThenInstanceIdAscending` | 一致 |

| CIA 标题版本 = 提交数 | `846d2cf9` | ✅ cmake | 一致 |
| 作弊页 / FPS 计数 | `1659ae00` 等 | ✅ `N3DSAm2r` 页面 | 各有实现 |

## 已采用（v0.3.1）

`b0c705fa`（光照贴图泄漏）、`e11eea27`（视图 surface 清理）、`14e9f9d7`（光照剔除）已移植。

`ddb0ae8e`（tile->alpha）、`f8f72a45`（自绘 surface 复制）与暂停页 320 版式我们早已实现。

## 建议顺序

1. 先移植 `b0c705fa` 的**暂停页 320 排版**——它能一次性解决我们 13/40 这类逐个补偿；
2. 再叠加**光照贴图泄漏**与**灯剔除**（独立、低风险）；
3. 视图 surface 清理与 tile alpha 次之；
4. 功能类（光照开关、全能力、传送）按需。
