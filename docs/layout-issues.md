# 暂停页 / HUD 版式问题（待处理清单）

## 现象与证据

| # | 现象 | 出现条件 | 关键证据 |
|---|---|---|---|
| 1 | 日志页正文**左右两端都被切字** | 宽屏、暂停→日志 | 文字画进 229×137 的 surface（`TextPos target=21 surf=229x137`），按 225 换行，但屏幕上左右都缺 |
| 2 | 日志页正文**右侧跑出屏幕** | 点对点 | 画面只有 320 宽，文本框坐标仍按 400 的布局（x=150 + 229） |
| 3 | 左下角"扫描中"**跑到屏幕外** | 宽屏 | `oScanning` 提示的锚点按 400 画布摆放 |
| 4 | HUD 最左（能量包图标）**左侧被切** | 宽屏与点对点 | `draw_gui` 原生实现的左边界没有随画布宽度调整 |
| 5 | 下屏能量 / 导弹 / 强力炸弹图标为**绿色方块** | 全部 | 下屏状态栏用的是自绘占位图标，不是 HUD 用的精灵 |

## 共同根因（推断，需验证）

端口里"画布宽度"有多处来源：

- `oControl.widescreen` / `widescreen_space`（游戏变量，会被游戏自己重置）
- `gAm2r.hudInset` / `gAm2r.hudLeftInset`（`draw_gui` 用的边距）
- 渲染器的 `frameOffset` / `portOffset`

各处分别取值，没有统一来源，于是出现"右侧超、左侧切、框宽对但文字溢出"等互相矛盾的现象。此前多轮尝试只改其中一处，按下葫芦浮起瓢。

## 处理方案

1. **统一画布宽度来源**：新增一个函数返回"当前画布宽"（320 或 400），
   `draw_gui`、暂停页边距、日志页文本框都从它算。
2. **HUD 左右边距**：左块按 `画布宽` 居中，右块用 `250 + space`（space 由画布宽推出，而非读游戏变量）。
3. **暂停页**：`widescreen` / `widescreen_space` 在暂停期间强制 0（已实现，待验证），
   并确认 1x 模式下暂停页不套 400 的坐标。
4. **下屏图标**：把 `n3ds_livemap.c` 里自绘的绿色方块，换成 HUD 使用的同一批精灵
   （能量包 / 导弹 / 超级导弹 / 强力炸弹的 tpag）。

## 验证方法

每项单独出测试包，用日志 + 截图核对，**不要一次改多处**。
日志已确认可用的定位字段（诊断版）：`TextPos`（文字落点与目标 surface）、`SurfDraw`（贴屏坐标）、`TextW`（首行宽度）。
