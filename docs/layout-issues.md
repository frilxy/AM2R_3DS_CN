# 暂停页 / HUD 版式问题（V1.10 后状态）

## 已解决（V1.10）

| # | 现象 | 修法 | 证据 |
|---|---|---|---|
| 1 | 宽屏能量读数左端被切（`99` 只剩右边 9） | HUD 左块补 13 列裁剪补偿 | 宽屏日志 `picture 400 … hud left 0`，游戏按 426 画布排版 |
| 2 | 点对点/拉伸 HUD 左端被切 | 左块补偿 13（实测正确） | `[Point] picture 320x240 at (40,0) … hud left 0` |
| 3 | 点对点扫描提示出界（"扫"字被切） | 该文字右移 40 | `ScanGlyph: cursorX=-19 drawX=-18 screenX=-18` |
| 4 | 下屏弹药图标不反映当前选择 | 按 `global.currentweapon` 选帧（HUD 同款高亮帧） | — |
| 5 | 地图标题加粗 | 试过后按要求取消 | — |

## 未解决

**日志页正文在部分入口下左右两端缺字。**

已确认的事实：

| 项 | 值 |
|---|---|
| 对象 | `oLogScreenControl` |
| 文字目标 | surface **229×137** |
| 文字落点 | surface 内 x=2（变换后 screen 2） |
| 换行宽度 | 225（已按框宽修正） |
| 贴屏位置 | screen **160**，宽 229 |
| 观察 | 文字两端仍缺字；点对点下右侧溢出屏幕 |

已排除：

- 框太窄（已从 149 改到 229，无效）
- 建框时机（改为创建时修正，无效）
- 换行宽度（改成 225，无效）
- 字体水平缩放（`scaleX = 1.0`，换算无效）
- HUD 补偿参数（与本页无关）

**下一步唯一没测到的环节**：`draw_surface` 贴屏时的**源矩形**（`src`）。若 `src` 宽被算成 149 而 surface 是 229，就会只贴左半、右侧留黑——这与现象完全吻合。测试版日志里加一行 `SurfDraw: id=… src=…` 即可确认（注意过滤条件要 `y>200 && x<60` 之类，否则会被 HUD 绘制吃光预算）。

## 教训（避免重复踩坑）

1. **按对象名找实例会静默失败**——先确认名字存在，或改用更稳定的特征（如 surface 尺寸）。
2. **诊断代码必须确认被编译进去**：官方构建带 `-DN3DS_KEYBOARD_MIRROR=OFF`，写在对应 `#ifdef` 里的代码会被整段删掉，表现为"改了没反应"。
3. **诊断预算要按目标过滤**，否则会被高频绘制（HUD、特效）吃光。
4. **一次只改一处、并验证符号生效**，比连续改多处更快。
